Goals

Provide a template for an HTML5 document which follows best-practices for presenting written instructions for typical computer science assignment, tutorial or project.    The ZJW GI template features include the following (see also the end users manual Help.html [work-in-progress]):
  1. CSS Formating and <templates>:
    1. Provide for <span> classes that visually designate simple content such as file names, code variable name, function names, user input, etc.
    2. Support for <span>,<div> and <table> classes that designate complex structured content typically found in instructions for programming projects such as:
      1. Shell script (CLI) code with annotations
      2. Zoomable screen captures
      3. [Ideally] Embedded video with associated written instructions whose written steps each include a button that advanced the video to the video segment illustrated that written step.
      4. ... other stuff ...
  2. Rubric Generation: Use HTML data- attributes that encode the points that each exercise and itemsin the assignment are worth and then automatically generate a rubric <table> from these data- attribute annotations.
  3. Grader Rubric::  generate www document (static page) that grader can use to comment and grade assignment.    .html doc should calculate final graded, allow entering of comments for each rubric item, and be transmitted to student ...? what else ?....
    Document could be uploaded to Canvas for each student or git added directly to the student's project repo.   
    1. Export format?   HTML, HTML printed to PDF?
  4. Document Variables: Use HTML data- attributes to support automatic string replacement of named "document variables" in the document text with text strings specific to the assignment.   For example, the in an instruction document, shell CLI examples may display a path name that user is working in.   The path name text often is specific the assignment name. The HTML written for displaying the shell CLI examples should refer to a "document variable" that will be replaced by a designated text string defined globally in the assignments meta data. This allows for easier maintenance when one inevitably changes a instruction document's project name.
  5. The core ZJW GI HTML5 document should be a static web page, but otherwise a document derived from ZJW GI template user must be able to include any HTML5 content -- SVG, WebGL, Canvas, etc. -- in their instruction document.   This is where my occasionally attempt to use Content Management Systems, Learning Management Systems, etc. always fails me..
  6. The ZJWGI is made a git submodule of a the your my-project and an initialization script makes symbolic links from the ZJWGI provided component file's directories into corresponding locations in the directory structure of my-project
  7. A .html paged derived from the ZJW GI template, only requires altering the content of my-project files without needing to modify code modules and components provided by the ZJW GI code.
  8. Users of ZJW GI template may contribute updates, improvements, bug fixes, to the ZJW GI code modules and components by making a git fork of the ZJW GI template.git submodule and linking my-project to their git fork

  9. Q&A Feature [7/15/2025: experimental, non deployed] - see notes below

  10. [FUTURE]:
    1. Provide functionally that allows common HTML5 editors such as BlueGriffon instantied the various components listed in #1 using the HTML5 <template> mechanism rather than copy and pasting example HTML code.
    2. If above is not feasibly in a short amount of time, provide a simple builtin HTML5 editor based on, that is augmented with GUI that can insert the <template>'s, and format selected text with with specialized <span> classes discussed in 1.a

  11. [CAVEATS]

    1. Only support the Chrome browser: All my courses HTML5 based projects require the student verify their project code runs in Chrome.  This is the target browser the TA uses for testing all assignments.  Neither I, nor students in most CS courses, have time to address all the madness of cross-browser compatibility.  That type of code development requirement is typically only appropriate in specialized courses in "Web Application Developement" or perhaps "Software Engineering".   Give that all students must install Chrome on their computers for my courses, it is reasonable to for the ZJW GI code and components to only target and be tested using the Chrome browser.   (The only alternative is to build the ZJWGI template ontop of a yet-another-layer API for cross browser compability, and I don't have the person-power resources to do that.  TA's don't work during summers when I don't teach classes which is when I can develop ZJW GI).

Notes

Q&A Feature

UNCC IT secuirty  policy makes it pretty much impossible to (1) run you own www server on campus and (2) get permission from UNCC services such as Gmail to accept XMLRequests [^] from your own off-campus server.  The only mechanism I can find to have a static www page launch a email to a UNCC Google Group is via the mailto URI scheme (elaborated on below).

The mailto URI scheme appears to disallow the pre-composed email body to have anything other than plain text.  Possibly the static www page could copy content to the browser clipboard and then the user could paste it into the launched Gmail compose browser tab in order to transfer an exact visual representation of the text the user selected in Q&A mode.

Directory Structure

Status:  [under revision; below is a duplicated of version2]

Note the file organization for a assignment description page using ZJW GI uses symbolic links.   These are ubiquitous on all OS's forever -- except MS Windows which eventually supported them (see mklink /D).  

The directory structure of an assignment description that uses ZJW GI is as follows:

  • my-project/
    • */*       | files and directories of my-project stuff that should not be transferred to the published website
    • scripts/zjwgi     | symlink to ./site/git_modules/zjwgi/scripts/zjwji
    • site/           | this contains files that are published to the web
      • index.html        | project specific index.html that is initiated with a copy of ./git_modules/zjwgi/site/index.html
      • html/             | additional my-project .html if applicable files
        • zjwgi/         | symlink to ../git_modules/zjwgi/site/html/zjwji
      • images/             | contains my-project .image files
        • zjwgi/         | symlink to ../git_modules/zjwgi/site/images/zjwji
      • videos/
        • zjwgi/         | symlink to ../git_modules/zjwgi/site/videos/zjwji
      • scripts              | contains my-project .js and .ts files
        • /zjwgi/         | symlink to ../git_modules/zjwgi/site/scripts/zjwji
      • css/                   | contains my-project specific .css files 
        • zjwgi/          | symlink to ../git_modules/zjwgi/site/csszjwji
      • git_modules/
        • zjwgi/             git submodule that comes from https://gitlab.com/zwartell/zjw-generic-instructions.git
          • scripts/     | scripts used for publishing and managing published to web such as sftp uploads, checking for broken hyperlinks, etc.
          • docs/        | documentations on using the ZJW GI template
          • site/
            Note:  The extra /zjwgi subdirectory structures below allow the template index.html's path names to scripts, css files, etc. to work correctly when the index.html is copied to my-projects/index.html as an initial template
            • scripts/zjwgi/    |  ZJWGI .js and .ts. files
            • css/zjwgi/          | ZJWGI .css files
            • images/zjwgi/   |  ZJWGI images files
            • videos/zjwgi/    |  ZJWGI videos files
            • index.html        |  template .html file to be copied your my-project/index.html to as a starting template for you project
            • zjwgi/               |  extra pages meant for distribution to ZJW GI based websites
              • help.html       | end-user documentation of the typo graphic font conventions and UI features provided in ZJW GI based assignment pages
