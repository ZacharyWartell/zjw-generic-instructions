Goals

ZJW Generic Instruction (ZJW GI) provide a template for creating an HTML5 document whose purpose is to describe written instructions for a computer science assignment, tutorial or project.    ZJW GI provides the features below:
  1. CSS Formatting and <templates>: 
    1. CSS files provide for <span> CSS classes that visually designate  content such as file names, code variable name, function names, user input, etc.
    2. CSS files provide <span>,<div> and <table> CSS classes that designate structured content typically found in instructions for programming projects such as:
      1. Shell script (CLI) code with annotations
      2. Zoomable screen captures
      3. [WIP] Embedded video with associated written instructions whose written steps each include a button that advanced the video to the video segment illustrated that written step.

    Example: See Typographics Conventions
  2. Rubric Generation: A ZJW GI based .html document can use HTML data- attributes to designate the points that each instruction item is worth.  ZJW GI automatically generates a rubric <table> from these data- attribute values.   The data- attributes support options such as evenly distributing the points from a instruction item across its component instruction items.
    Example: See Rubric
  3. Gradable Rubric:  The ZJW GI generated rubric has a TA grading mode.  When enabled, the grader can click check boxes for each item in the rubric table that a student completed and add a text comment for each item.   The grader can export the rubric table to a static .html file that can be forwarded to the student.
    Example    : See Rubric and TA Instructions Typographics Conventions
  4. Document Variables: A ZJW GI provide custom HTML data- attributes that support automatic string replacement of named document variables in the document text.   For example, an instruction document may have shell CLI example code that displays various path names.   The path name's text often is specific the assignment name. The path names can be written to refer to a named document variable.   When rendered, the document variable will be replaced by a string whose value is set in the .html file meta data. This eases document maintenance when one changes the document's project name, project number, active semester, etc.
  5. Static Web Page:  A ZJW GI document is generally a static web page.  The .html document writer can include any HTML5 content -- SVG, WebGL, etc. -- in the .html page.   This is unlike a Content Management System, but it requires the document writer develop their page using a HTML code editor.   However, at present ZJW-GI documents have a simple built in WYSYWIG HTML editor from my zxw-mvc project.  The editor only edits the local DOM but can save the DOM to a local file which the web master can upload to the public website.
  6. Straight HTML:  A ZJW GI modules are written in vanilla HTML5.   No libraries such as jQuery, React, Vue, etc. are used.
  7. Using ZJW GI:  A separate .git repository https://gitlab.com/zwartell/zjw-generic-instructions-template/ provides template for creating a ZJW GI based .html document.


  8. Q&A Feature [7/15/2025: experimental; code is deployed, but disabled by default] - see notes below
  9. Progressive Web App:  [experimental; not deployed] Support a ZJW GI derived webpage as progressive web app that a student can download (i.e. install) on their computer, so they do not need to be online to read a ZJW GI derived .html document.

  10. [FUTURE]:
    1. [Work in Progress] Integrate a simple builtin HTML5 editor into ZJW GI which can insert ZJW GI <template>'s into the DOM and initialize them so ZJW GI will setup required eventListeners that implement their interactive features.   Use https://developer.mozilla.org/en-US/docs/Web/API/Window/showSaveFilePicker to save the DOM changes to an .html file on the local file system.
    2. [Abandoned] Investigate way to provide plugins for common HTML5 code editors such as BlueGriffon that will instantiate the ZJW GI provided <template> rather than the document writer having to copy and paste HTML code.

  11. [CAVEATS]

    1. Only tested on the Chrome browser: All my courses HTML5 based projects require the student verify their project code runs in Chrome.  This is the target browser the TA uses for testing all assignments.  Neither I, nor students in most CS courses, have time to address all the madness of cross-browser compatibility.  That type of code development requirement is typically only appropriate in specialized courses in "Web Application Developement" or perhaps "Software Engineering".   Give that all students must install Chrome on their computers for my courses, it is reasonable to for the ZJW GI code and components to only target and be tested using the Chrome browser.   (The only alternative is to build the ZJWGI template ontop of a yet-another-layer API for cross browser compability, and I don't have the person-power resources to do that.  TA's don't work during summers when I don't teach classes which is when I can develop ZJW GI).

Q&A Feature 

Status:  [Experimental - Deployed - Only Activated under "Beta" Mode, Not Currently Used or Advertised to Students]


UNCC IT security  policy makes it pretty much impossible to (1) run you own www server on campus and (2) get permission from UNCC services such as Gmail to accept XMLRequests [^] from your own off-campus server.  The only mechanism I have found to allow a static www page launch a email to a UNCC Google Group is via the mailto URI scheme (elaborated on below).

The mailto URI scheme appears to disallow the pre-composed email body to have anything other than plain text.  Possibly the static www page could copy content to the browser clipboard and then the user could paste it into the launched Gmail compose browser tab in order to transfer an exact visual representation of the text the user selected in Q&A mode.

    User Guide

    Overview

    α-0.1.56

    zxw-editor is an experimental 'in-place' HTML editor.

    • zxw-editor.html can be saved to a local file in Chrome. The resulting saved local .html file can be openned directly in Chrome and further edited in Chrome. The saved local .html embeds the zxw-editor code itself. Therefore once saved, the saved .html is completely standalone and editable.
      • zxw-editor is a single page, static webpage.
      • zxw-editor does not communicate to any server.
    • zxw-editor neither requires nor uses any 3rd party framework (React, Vue, Angular).
    • zxw-editor leverages contentedible and showSaveFilePicker to save edits to the webpage (i.e. the local DOM) to a local file.
    Caveats:
    • zxw-editor assumes the user is comfortable and familiar with using the Chrome Inspector to edit the DOM in addition to editing the contentedible <div> directly using the browser's inherent contentedible editing features.
    • zxw-editor is only tested on the Chrome browser.
    • zxw-editor is α software. A common Computer Science 101 programming assignment at universities like MIT is to write a program that prints out an exact replica of itself. This is tricky. The more complicated the programming language being used, the trickier it is. Undoubtedly, the zxw-editor 'save-itself-to-a-file' algorithm still does not handle all situations.
